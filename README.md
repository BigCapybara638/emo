# Чудо Обувь — WPF

Компактное приложение на C# / WPF / .NET 10 / SQL Server. Каталог, карточка
товара, заказы и их состав открываются в одном окне с кнопкой **Назад**.
Авторизация осталась прежней: только логин из `Users`, без пароля;
исходный запрос поиска пользователя сохранён.

При запуске сначала появляется только окно входа. Каталог создаётся после
успешной авторизации и закрывается перед выходом из аккаунта.
На окне авторизации есть кнопка **Войти как гость**: без ввода логина можно
просматривать каталог, искать товары и открывать их карточки. Корзина,
оформление и управление заказами гостю недоступны. Для входа в аккаунт
из гостевого режима нажмите **Выйти**.

## Открытие в Visual Studio 2026

1. В Visual Studio Installer установите **Разработка классических приложений .NET**
   и SDK **.NET 10**.
2. Клонируйте `https://github.com/BigCapybara638/emo.git`, ветка **main**.
   Если проект уже клонирован, переключитесь на `main` и получите изменения.
3. Выберите **Файл → Открыть → Проект или решение**, откройте `emo.slnx`.
4. Подготовьте базу по инструкции ниже. Дождитесь восстановления NuGet-пакетов.
5. Если требуется, назначьте проект `emo` запускаемым. Нажмите **F5**.

Интерфейс находится в `emo/MainWindow.xaml`, обработчики — в `.xaml.cs`,
работа с БД — в `DBHelper.cs`, расчёт скидки — в `Models.cs`.

## База данных

SQL Server и SSMS устанавливаются отдельно. Скрипты выполняйте в нужной базе.

**Если база `demo` уже есть:** сначала выполните `database/rename_tables.sql`,
затем `database/upgrade.sql`. Переименование сохраняет данные и внешние ключи;
при конфликте имён изменения отменяются.
Если таблицы уже имеют имена без `$`, первый скрипт ничего не меняет.
`upgrade.sql` также переименует старые поля `Наименование товара` → `Наименование`
и `Дата заказа` → `Дата_заказа`, если это требуется.
`upgrade.sql` добавляет сохранённую цену и процент скидки к позициям заказа.
Скрипт можно запускать повторно: уже сохранённые цены он не меняет.

**Если базы нет:** создайте пустую базу `demo` в SSMS, затем последовательно
выполните `database/create.sql` и `database/upgrade.sql`.
`create.sql` создаёт связанные таблицы и загружает исходные данные из
сохранённого в репозитории `import.xlsx`; в непустую базу его запускать нельзя.
Скрипт сам создаёт базу **demo**, если её ещё нет. Таблицы соответствуют
предоставленной структуре: девять `id` с `IDENTITY`, размер `DECIMAL(4,1)`,
цена товара `DECIMAL(12,2)`, дата `Дата_заказа DATETIME2(0)`, название товара
`Наименование` и ключ `Order_stock (id_order, id_stock_items)`.
Старые таблицы скрипт не удаляет. Полное совпадение типов и `IDENTITY`
обеспечивается при создании новой базы; `upgrade.sql` не перестраивает
имеющиеся столбцы `id`. Для уже созданной по предоставленной схеме базы
достаточно выполнить `upgrade.sql` для сохранения цен заказов.

В начале `emo/DBHelper.cs` измените `Data Source=USERS\SQLEXPRESS` на имя своего
SQL Server, например `localhost` или `.\SQLEXPRESS`. `Database=demo` и
`Integrated Security=True` означают базу `demo` и вход под учётной записью Windows.
Вместо изменения файла можно задать переменную среды `EMO_CONNECTION` с полной
строкой подключения перед запуском Visual Studio или приложения.

Логины из исходных данных: `isivanov` — администратор, `negorov` — менеджер,
`asidorova` — клиент. При необходимости смотрите `Users` после импорта.

Старые заказы не содержали исторической цены: миграция восстанавливает её
по имеющейся цене товара и истории заказов на дату заказа. Если цены или
историю раньше меняли, точную старую стоимость восстановить невозможно.
Для новых заказов цена и скидка сохраняются при оформлении.

## Функции и требования КИМ

- Каталог с изображениями и заглушкой, категориями, производителем, составом,
  описанием, остатками «много» / «мало». При остатке ≤3 карточка светло-красная.
- Скидка **25%**, если товар не заказывали в предыдущем календарном месяце
  относительно текущей даты. Учитываются все размеры и весь последний день
  месяца. Карточка показывает итоговую цену и процент скидки.
- Совместные поиск по названию/описанию/составу, фильтр категории и сортировка
  цены работают сразу; при возврате из карточки фильтры сохраняются.
- В карточке: доступные размеры, количество, добавление в корзину и
  **Оформить сразу**. Любой новый заказ требует подтверждения; до подтверждения
  товары не списываются, от заказа можно отказаться кнопкой **Назад**.
- В составе заказа показываются модель, производитель, размер, количество,
  сохранённая цена за единицу, скидка и итоговая сумма. Цена совпадает с
  выбранной карточкой и не меняется при последующем изменении цены товара.
- Менеджер и администратор видят заказы, создают новый заказ с выбором даты и
  ФИО клиента, добавляют товары через **тот же каталог**. Отдельной формы
  добавления товара нет. Корзина использует тот же экран состава заказа.
- Администратор может менять дату существующего заказа и удалять позиции.
  Количество меняется кнопкой **Изменить количество**: в корзине и новом
  заказе — любым авторизованным пользователем, в оформленном — администратором.
  При удалении заказа/позиции товары возвращаются на склад; пустой заказ удаляется.
- Запись заказа, его состава и остатков выполняется в одной транзакции.
  Повторная проверка остатков предотвращает перепродажу, в том числе при
  одновременном оформлении. Ошибка не оставляет частично созданный заказ.
- ФИО пользователя справа вверху, заголовки страниц, логотип, иконка, сообщения
  об ошибках и подтверждения действий.
- При наведении на кнопки, поля, списки и заголовки таблиц появляются
  описания. Карточки показывают описание товара; ячейки — полное значение.
  Буквы/знаки и некорректная вставка в количество блокируются, ноль,
  переполнение и превышение остатка не позволяют оформить позицию.
- В списке заказов названия полей — `Дата_заказа`, `Фамилия`, `Имя`, `Отчество`;
  в составе — `Наименование`, `Производство`, `Размер`, `Количество`, `Цена`.
  Процент `Скидка` хранится миграцией, `Сумма` вычисляется.
- Фильтр содержит все категории БД, даже пока не имеющие товаров.

## Проверка и сборка

```powershell
dotnet build emo.slnx -c Release
dotnet publish emo/emo.csproj -c Release -o artifacts/app
```

`artifacts/app/emo.exe` запускается при установленном .NET 10 Desktop Runtime.
В этой же папке должны оставаться DLL и каталог `Resources`.

Регрессионные проверки используют отдельную базу с именем `emo_validation_*`.
Создайте её, выполните оба SQL-скрипта, затем:
В тестовой копии `create.sql` сначала замените **все три** начальных
упоминания `demo` (проверка, создание и `USE`) на имя тестовой базы.
Исходный `create.sql` всегда выбирает `demo` независимо от текущей базы в SSMS.

```powershell
$env:EMO_TEST_CONNECTION = 'Data Source=localhost;Database=emo_validation_schema_20261112;Integrated Security=True;TrustServerCertificate=True'
dotnet run --project tests/Regression.csproj
```

Тесты меняют только отдельную тестовую базу и проверяют границы месяца,
скидку, сохранение цены, транзакции, остатки, роли, отображение цены и навигацию.
Они отказываются работать с базой, имя которой не начинается на `emo_validation_`.
